# 產生訓練菜單原則

依目前健身管理 Project 的實際做法整理。之後改原則時改這份。

## 場地與器材

1. **先確認場地**：居家或健身房（或其他），菜單必須在該場地做得到。
2. **居家必看** [`equipment.yaml`](../equipment.yaml)：啞鈴總重 20 kg、啞鈴床、瑜珈墊、彈力繩；不得假設有槓鈴、器械或超出清單的器材。
3. **負重上限**：居家啞鈴總重不超過 20 kg；成對拆分未知時寫明假設（例如約 10 kg／手），無法合理估計則標「自行評估」。
4. **勿硬追健身房重量**：居家負重遠低於近期健身房紀錄時，改以高次數、單邊、節奏（離心）、彈力繩維持刺激。

## 菜單內容必備

5. **每個主動作都要有**：組數 × 次數（或時長）、**建議重量**（或「自行評估」）、**簡短注意事項**（1–3 句）。
6. **結構完整**：熱身 → 主課 → 緩和；標預估時間與組間休息。
7. **單次可執行**：預設給「下一練／單次課」，不是一次重寫整份年度課表（除非明確要求）。
8. **動作命名**：盡量與 [`program.yaml`](../program.yaml)／日誌風格一致，方便事後寫入 `logs/YYYY-MM-DD.yaml`。

## 選練什麼（拉／推／腿等）

9. **以 repo 日誌為準**：依最近訓練日、間隔天數、粗組數／量，判斷下一練主軸；樣本少或有空檔要註明限制。
10. **給出主建議 + 次選**：例如主練腿、次選拉；說明簡短理由即可。

## 匿名與紀錄

11. **遵守 [`SCHEMA.md`](../SCHEMA.md) 匿名規則**：不寫姓名、住址、可辨識店名、帳號、照片等。
12. **菜單可放 Project Context `docs/`**；實際練完的組數重量進 GitHub 日誌，不把聊天當資料庫。
13. **推送**：日誌／器材等 repo 變更經確認後 commit 並推 `main`（使用者已建立此習慣時）。

## 產出形式

14. **聊天給可掃的摘要表**；細節連到 Context 完整文件。
15. **不確定就標明**：器材級距未知、彈力繩無 kg、疼痛風險等，用「自行評估」或降低難度選項，不裝確定。
